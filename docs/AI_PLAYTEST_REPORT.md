# Neon Pulse Protocol — AI 플레이테스트 및 개선 보고서

- 테스트 일자: 2026-08-02
- 테스트 규모: AI 플레이어 9명
- 대상 빌드: 3곡 × 3난이도 웹 MVP
- 곡: Circuit Bloom / Neon Pulse Protocol / Overclock Horizon

## 결론

현재 빌드는 **플레이 가능한 리듬 게임 MVP**다. 음악 재생, 4레인 입력, 판정, 콤보, 점수, 오버드라이브, 결과 화면, 모바일 터치까지 핵심 루프가 이어진다. 테스트에서 가장 많이 겹친 문제는 타격음 부재, 빈 탭 연타 악용, 과도하게 오래 유지되는 오버드라이브, EARLY/LATE 정보 부재, 작은 모바일 화면의 스크롤, 결과 보상 부족이었다.

이번 개선에서는 위 공통 문제를 우선 해결했다. 다만 곡별 채보를 완전히 음악적으로 다듬는 작업과 상업 이용 증빙 정리는 출시 전 별도 단계로 남겨 둔다.

## 플레이어별 테스트 결과

### 1. 처음 접한 플레이어

- Circuit Bloom EASY에서 D/F/J/K, 고의 미스, 일시정지와 재시작을 시험했다.
- 기본 난이도와 키 안내가 명확하고, 실패로 즉시 종료되지 않아 진입 장벽이 낮다고 평가했다.
- 첫 노트 예고와 카운트다운, EARLY/LATE, 일시정지 후 곡 선택 동선이 필요하다고 제안했다.
- 한글과 영어가 섞인 UI, 입력 오프셋 설명 부족도 지적했다.

### 2. 숙련 리듬 게임 플레이어

- Overclock Horizon HARD에서 고속 입력, 점수 구조, 일시정지를 시험했다.
- 오디오 시간을 기준으로 판정하는 구조와 40/80/150ms 판정창, 한글 IME에서도 작동하는 물리 키 입력을 장점으로 꼽았다.
- 빈 탭에 실질적인 불이익이 없어 연타가 유리하고, 오버드라이브가 거의 영구 유지되며, 타격음·고정 노트 속도·EARLY/LATE 부재가 손맛을 제한한다고 평가했다.
- 동시 노트 판정 문구가 서로 덮이고 키 리셉터가 눌린 모습으로 반응하지 않는 문제를 찾았다.

### 3. 채보 디자이너

- 세 곡이 같은 패턴과 고정된 구간을 공유해 곡별 개성이 약하다고 평가했다.
- Overclock Horizon의 실제 전개는 약 44–68초 드롭, 68–84초 브레이크, 84–112초 최종 드롭인데 기존 채보가 각각 약 4초 늦게 반응한다고 분석했다.
- 세 곡 모두 같은 레벨 표기를 쓰는 대신 곡별 체감 난이도를 구분할 것을 권했다.
- EASY의 동시치기 부재, 전 난이도의 롱노트 부재, 반복 잭 패턴은 이후 채보 개선 과제로 남겼다.

### 4. 모바일 플레이어

- 390×844에서는 레인 폭, 터치 입력, 고해상도 캔버스가 양호했다.
- 360×640에서는 곡 선택 화면의 시작 버튼이 아래로 밀리고, 내부 스크롤이 본문으로 이어지며, 상단 HUD가 잘릴 수 있다고 보고했다.
- 최소 44px 터치 목표와 진동 설정을 요청했다.

### 5. 접근성 검토자

- 네이티브 버튼, 물리 키 코드, 한국어 문서 언어 설정은 긍정적으로 평가했다.
- 캔버스 플래시·화면 흔들림이 `prefers-reduced-motion`을 따르지 않고, 선택 상태와 진행 바의 의미, 다이얼로그 역할, 키보드 포커스 표시가 부족하다고 지적했다.
- 상태 변화를 보조 기술에 전달할 라이브 영역도 필요하다고 제안했다.

### 6. 타격감·연출 검토자

- 파티클, 링 펄스, 화면 흔들림의 기본 방향은 좋다고 평가했다.
- 음악에 묻히지 않는 짧은 타격음이 최우선이며, PERFECT/GREAT/GOOD의 시청각 차이를 더 분명하게 할 것을 요청했다.
- 전체 화면 플래시 빈도와 오버드라이브 유지 시간을 낮추고, 레인 단위 피드백과 이펙트 축소 옵션을 권했다.

### 7. 점수·밸런스 검토자

- 빈 탭 연타와 오버드라이브 유지가 점수 경쟁을 왜곡하고, 콤보 배율이 정확도보다 강하다고 평가했다.
- 결과 화면에 최종 점수, NEW BEST, FULL COMBO가 없어 플레이 후 보상이 약하다고 지적했다.
- 곡별 권장 레벨 범위는 Circuit 2/5/8, Neon 3/6/9, Overclock 4/7/10으로 정리했다.

### 8. 프런트엔드 엔지니어

- 실제 재생과 일시정지, 스페이스 재개, 오디오 시간 기반 판정이 정상 작동하고 콘솔 오류가 없음을 확인했다.
- 초기 템플릿용 테스트가 현재 게임과 무관해 실패하고, 초기 설정 복원 Effect에 린트 오류가 있다고 보고했다.
- 매 프레임 전체 노트를 순회하는 부분, 오디오 재개 실패 처리, 입력과 시각 오프셋 분리는 기술 개선 과제로 제안했다.

### 9. 출시 검토자

- 핵심 게임 루프는 MVP 수준이지만 익명 접속은 비공개 인증 화면에서 막힌다고 확인했다.
- GitHub 동기화 상태, 테스트·린트 품질 게이트, 음악 상업 이용 권리와 크레딧 증빙을 출시 전 필수 항목으로 분류했다.
- 설정, 피드백 수집, 빌드 버전 표기와 실제 프로젝트에 맞는 README도 권했다.

## 이번에 반영한 개선

### 플레이 감각

- PERFECT/GREAT/GOOD마다 높이와 질감이 다른 짧은 Web Audio 타격음을 추가했다.
- 판정 문구 아래에 EARLY/LATE를 표시한다.
- 동시 노트의 판정이 덮이지 않도록 레인별 피드백을 독립 표시한다.
- 누른 레인의 리셉터가 즉시 밝아지고 커지는 입력 반응을 추가했다.
- 시작과 동시에 음악 인트로 위로 3–2–1–GO 카운트다운을 표시한다.
- 전체 화면 플래시는 PERFECT에만 제한하고 강도를 낮췄다.

### 밸런스와 보상

- 빈 레인 탭은 콤보를 끊고 SYNC를 5 감소시켜 무작정 연타하는 전략을 막았다.
- 오버드라이브 충전량을 크게 낮추고, 발동 중 추가 충전을 막았다.
- 오버드라이브는 8초 동안 일정하게 소모된 후 0으로 초기화된다.
- 결과 화면에 최종 점수, NEW BEST, FULL COMBO를 추가했다.
- 곡별 레벨을 Circuit 2/5/8, Neon 3/6/9, Overclock 4/7/10으로 분리했다.

### 게임 오버와 긴장감

- 별도의 `CORE INTEGRITY` 체력을 추가했다. 오버드라이브 충전량과 생존 상태가 서로 다른 자원이 됐다.
- MISS 피해는 EASY 5, NORMAL 7, HARD 10으로 난이도에 따라 증가한다.
- 빈 레인 탭도 EASY 2, NORMAL 3, HARD 4의 피해를 받아 연타 방지 규칙과 생존 규칙이 연결된다.
- PERFECT는 체력을 0.8, GREAT는 0.3 회복해 정확한 플레이가 생존에도 직접 보상된다.
- 체력이 0이 되면 음악이 즉시 멈추고 진행률과 현재 점수를 보여 주는 GAME OVER 화면으로 전환된다.
- 게임 오버 화면에서 즉시 재도전하거나 곡 선택으로 돌아갈 수 있다.

### 채보

- 각 트랙이 고유한 구간 정보를 갖도록 구조를 바꿨다.
- Overclock Horizon의 드롭/브레이크/최종 드롭을 44/68/84/112초에 맞춰 기존보다 약 4초 빠르게 반영했다.
- EASY에는 드물게 1.5박, NORMAL/HARD에는 2–2.5박 길이의 HOLD 노트를 주기적으로 배치했다.
- HOLD 시작점을 판정창 안에서 누른 뒤 끝까지 유지해야 점수와 콤보가 확정된다.
- 끝나기 80ms보다 일찍 떼면 `BREAK`로 처리되어 MISS와 같은 체력 피해를 받고 콤보가 끊긴다.
- 키보드 keydown/keyup과 모바일 Pointer ID를 각각 추적해 동시 입력 중에도 HOLD 유지와 해제를 판정한다.

### 모바일과 접근성

- 100dvh 고정 셸과 내부 스크롤 차단으로 작은 화면의 이중 스크롤을 줄였다.
- 모바일 곡 선택 CTA를 하단에 고정하고 주요 버튼의 터치 높이를 44px 이상으로 맞췄다.
- HIT SFX, REDUCED FX, VIBRATION 설정을 추가하고 로컬에 저장한다.
- 운영체제의 모션 축소 설정을 첫 방문 기본값에 반영한다.
- 선택 버튼에 `aria-pressed`, 오버레이에 다이얼로그 의미, 진행 바에 수치 의미, 키보드 포커스 표시를 추가했다.
- 일시정지 화면에서 곡 선택으로 바로 나갈 수 있다.

### 품질 게이트

- 오래된 스타터 테스트를 현재 게임의 서버 렌더링, 3개 오디오 에셋, 판정·설정·접근성 핵심 기능을 확인하는 테스트로 교체했다.
- 초기 로컬 저장소 복원으로 발생하던 Effect 린트 오류를 제거했다.

## 남은 우선순위

### P0 — 공개 출시 전 필수

1. Flow Music/Lyria 생성물의 상업 이용 가능 범위, 계정 플랜, 생성 날짜를 캡처해 곡별 권리 증빙으로 보관한다.
2. 익명 공개 여부를 결정한다. 현재 사이트는 비공개 상태를 유지한다.
3. GitHub 기본 브랜치와 배포 커밋을 동기화한다.

### P1 — 플레이 품질

1. stems 또는 원본 오디오 분석을 바탕으로 세 곡의 채보를 수작업 보정한다.
2. 롱노트와 슬라이드 중 한 종류를 추가해 패턴 어휘를 넓힌다.
3. 노트 속도와 시각 오프셋을 입력 오프셋과 분리한 설정을 추가한다.
4. EASY 초반에는 연속 MISS 문구를 완화하거나 짧은 튜토리얼 구간을 제공한다.

### P2 — 운영

1. 빌드 버전과 크레딧 화면을 추가한다.
2. 익명 피드백 수집 경로를 만든다.
3. 최고 점수 외에 최고 정확도와 난이도별 클리어 배지를 별도로 저장한다.

## 다음 플레이테스트 권장 시나리오

1. Circuit Bloom EASY를 처음 플레이하고 카운트다운부터 결과 화면까지 이해되는지 확인한다.
2. Neon Pulse Protocol NORMAL에서 일부러 빠르고 늦게 눌러 EARLY/LATE가 보정에 도움이 되는지 확인한다.
3. Overclock Horizon HARD에서 빈 탭 연타로 점수를 얻을 수 없는지 확인한다.
4. 오버드라이브가 8초 뒤 확실히 종료되고 다시 충전되는지 확인한다.
5. 360×640 모바일 화면에서 곡 선택, 설정, 시작 버튼을 한 손으로 조작한다.
6. REDUCED FX와 진동 OFF 상태에서 모든 연출이 불편 없이 플레이 가능한지 확인한다.
7. 각 난이도에서 연속 MISS와 빈 탭으로 체력이 0이 될 때 음악이 멈추고 GAME OVER가 한 번만 발생하는지 확인한다.
8. HOLD를 끝까지 누르면 성공하고, 중간에 떼면 BREAK가 발생하는지 키보드와 멀티터치에서 각각 확인한다.
